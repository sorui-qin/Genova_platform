# EPSO Property Optimization

Protocol version: generation-2026-09. Sources: genova_runtime/epso_objectives.py, genova_runtime/entry_epso.py, deploy/EPSO.md.

## Seed and outputs

EPSO uses a complete seed molecule for 2D property optimization, unlike DELETE's 3D fragment editing. EPSO must bind a prepared Protein Context and uses its reference ligand by default. If the user explicitly overrides the seed, the actual file ID must be saved. Restoring a job must not silently change its input.

EPSO returns a CSV, trajectory, and metadata without generating original 3D poses. Any 3D conformations generated later by TarPass are docked results.

## Objectives and budget

EPSO can optimize `qed`, `sa`, `mw`, `logp`, `lipinski`, `hba`, `hbd`, `heavy_atom_count`, `similarity`, and `gnina_affinity` (disabled by default). Affinity uses the `seed_relative` mode and requires a validated receptor and docking box. Lower Gnina energy is better; candidates worse than the seed incur a penalty with twice the slope.

Objectives include lower bounds, upper bounds, ranges, target values, maximization, and minimization. The runtime definition validates the fields required by each mode. Weight and softness control the objective function; they are not experimental measurements. The number of particles and optimization steps jointly determine the computational budget and must satisfy the backend limit. Consult the runtime catalog for current default objectives, fixed parameters, particle counts, step counts, and the seed.

EPSO's `sa` objective uses a 0–1 definition. TarPass's `sa_score` is a different scoring field; their names, thresholds, and ranking semantics are not interchangeable. An objective-function score is not actual biological activity. Read actual results from the job and result services.
