# 智能体任务安全与证据检查

所有科学计算仍使用现有 Job、审批、Outbox 和 Worker。新增 `agent_research_tasks` 仅记录研究目的及判定状态；独立手动 `POST /api/v1/jobs` 不新增用途判定。

## 数据库升级

后端启动沿用既有迁移入口，执行 `VERSE/backend/migrations/20261029_research_safety.sql`。迁移增加研究任务表及会话、回合、工作流、持久规划请求的关联字段。历史记录首次继续、编辑或审批时按已有用户请求和保存方案判定，不批量重写历史结果。运行新后台进程前应完成该迁移；已有实例需备份数据库。

历史无任务标识的回合仅在服务器记录的原会话归属及创建时间证明其属于当前任务时绑定；显式新任务不会接收这种历史绑定。尚未判定、判定进行中或已阻断的任务均不可提交科学动作。

## 新建独立研究任务

继续使用现有回合接口：

```http
POST /api/v1/agent/sessions/{session_id}/turns
```

```json
{
  "client_request_id": "新UUID",
  "base_revision": 0,
  "intent": "new_task",
  "message": "独立研究任务的具体正常目标"
}
```

`base_revision` 使用当前会话版本。新任务单独判定，成功后切换当前研究任务并清空当前输入与工作流指针；既有记录保留。修改数量、引擎、重试和续做继承原任务。`research_task_id` 由后端分配，客户端不能设置安全状态。

前端输入新目标后点击“以此目标新建任务”。普通问答继续使用原入口及鉴权。

## 执行和输出

用途判定只判断请求能否被协助，不把缺少文档、结构或状态记录误作安全澄清；正常文档、概念和状态问答不要求额外陈述研究目的。首次安全判定同时判断请求的帮助类型和提供该帮助的实质风险，所有语言使用相同标准。明确高风险直接拒绝，不以证明用户动机或实际伤害为前提。只有首次判定仍需澄清时，才独立复核一次风险；复核发现明确风险则拒绝，不因较宽松的复核结果直接放行。复核期间任务仍在待审核状态。安全判定、条件复核与输出核查复用当前用户选择的模型、代理、认证及用量账本，不需要新增模型凭证；独立调用不代表独立模型。安全判定或条件复核失败返回可重试的 `SAFETY_CHECK_UNAVAILABLE`，不会将故障写成有害用途。

已确认有害目的的任务保持阻断；高层安全科普可只读回答。旧工作流、卡片、编辑器、恢复和后台推进共用任务状态。提交与展示前检查判定版本，模型调用期间释放数据库锁。

确认有害目的后，以一个事务取消关联 Job/JobTask 和待发送 Outbox，再更新既有 Redis 取消标记。已经开始的底层进程不强杀，不能将数据库取消状态当作进程已终止。判定服务暂时不可用会停止新增和续做操作，不将升级前已运行任务自动认定为有害。

正文通过证据核查后展示，工具进度继续即时更新。诊断说明由实际证据记录构造；原始文档和日志不取得审批、所有权或工具授权。输出核查直接接收后端会话状态（含准备 Job、提案、候选集和错误）与模型输出契约；它不因自身没有工具而认定主 Agent 无法读取状态。未检索到资料时不暴露空引用读取工具。预览与保存复用同一个后端分配的工作流 ID；未保存的候选预览不增加持久版本。输出核查接收即将保存的方案及待审批状态，保存成功后才展示答复。已启动方案的修改使用新 ID 和版本 1；数量快捷修改遵循相同规则。最终保存锁内复核预留身份，期间发生审批则返回 `PLAN_CHANGED`，要求重新预览。

## 本地验证

仅在独立分支验证；前端运行 `npm run build`，避免触发启动服务的 `predev`。隔离 PostgreSQL 回归覆盖迁移、任务隔离、阻断/故障、取消原子性、终态并发、Outbox、审批快照、版本刷新和已核文本事件发布。实验命令、源码哈希和结果放在项目根 `performance_results/`，不把临时实验脚本写入发布运行目录。
